# SEC-001: Mutating Tool Confirmation Hint

- **Category:** `security`
- **Default Severity:** `warning`
- **Penalty Points:** 8
- **Scope:** Tool-level
- **Specification:** [W3C WebMCP Safety Annotations](https://webmachinelearning.github.io/webmcp/)

---

## Overview

Tools that perform state mutations, financial transactions, database writes, or destructive actions (such as deleting data, placing an order, or transferring funds) must declare safety annotations to prevent autonomous LLMs from executing them without explicit human confirmation.

The WebMCP specification provides the `consequentialHint` and `confirmationHint` annotations for this purpose. When set to `true`, host user-agents and browser AI harnesses prompt the human user with a confirmation modal before running the tool.

---

## Detection Heuristic

This rule inspects:
1. Tool names starting with mutating action verbs: `delete_`, `remove_`, `cancel_`, `drop_`, `destroy_`, `purge_`, `checkout_`, `pay_`, `order_`, `buy_`, `update_`, `edit_`, `modify_`, `create_`, `send_`, `post_`, `submit_`, `insert_`, `transfer_`.
2. Tools with `annotations: { destructiveHint: true }` or `annotations: { readOnlyHint: false }`.

If any of these conditions are met and neither `consequentialHint: true` nor `confirmationHint: true` is present, SEC-001 triggers a warning.

---

## Failure Condition

```javascript
// Non-compliant: Modifies order or charges credit card without confirmation hint
navigator.modelContext.registerTool({
  name: "checkout_cart",
  description: "Processes payment and charges the user card.",
  inputSchema: { type: "object", properties: { cardId: { type: "string" } } }
});
```

---

## Remediation

Add `annotations: { consequentialHint: true }` to the tool definition:

### ✅ Compliant Example

```javascript
navigator.modelContext.registerTool({
  name: "checkout_cart",
  description: "Processes payment and charges the user card for items in their shopping cart.",
  annotations: {
    consequentialHint: true,
    readOnlyHint: false
  },
  inputSchema: {
    type: "object",
    properties: {
      cardId: {
        type: "string",
        description: "Payment method identifier"
      }
    },
    required: ["cardId"]
  }
});
```

# BP-002: Input Schema Parameter Check

- **Category:** `best-practices`
- **Default Severity:** `info`
- **Penalty Points:** 2
- **Scope:** Tool-level
- **Specification:** [W3C WebMCP Zero-Parameter Tools](https://webmachinelearning.github.io/webmcp/)

---

## Overview

Some tools genuinely take zero input arguments (e.g. `clear_cart`, `get_current_location`, `logout`). However, an empty `properties: {}` block is frequently an accidental omission during development where the author forgot to declare parameters.

This rule raises an informational note on tools with 0 defined properties to remind developers to document the zero-argument behavior clearly in the tool's description.

---

## Evaluation Condition

Triggers an `info` level finding whenever `Object.keys(inputSchema.properties || {}).length === 0`.

### ℹ️ Informational Example

```javascript
navigator.modelContext.registerTool({
  name: "get_current_user",
  description: "Fetches user info",
  inputSchema: {
    type: "object",
    properties: {}
  }
});
```

---

## Remediation

1. If the tool was intended to accept arguments (e.g. an ID or filter), add them to `inputSchema.properties`.
2. If the tool is legitimately zero-argument, clarify in the description that it operates on the current session/page state without requiring parameters.

### ✅ Compliant Example

```javascript
navigator.modelContext.registerTool({
  name: "get_authenticated_user_profile",
  description: "Fetches profile information for the currently active authenticated session. Requires no parameters.",
  inputSchema: {
    type: "object",
    properties: {}
  }
});
```

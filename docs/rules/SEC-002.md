# SEC-002: Conflicting Safety Annotations

- **Category:** `security`
- **Default Severity:** `error`
- **Penalty Points:** 10
- **Scope:** Tool-level
- **Specification:** [W3C WebMCP Safety Annotations](https://webmachinelearning.github.io/webmcp/)

---

## Overview

A tool cannot simultaneously declare `readOnlyHint: true` and `destructiveHint: true`. A read-only operation by definition cannot perform destructive mutations or deletes. Contradictory annotations confuse host safety guards and produce undefined behavior in client execution sandboxes.

---

## Failure Condition

This rule fails with severity `error` whenever a tool asserts both:
- `annotations.readOnlyHint === true`
- `annotations.destructiveHint === true`

### ❌ Non-Compliant Example

```javascript
navigator.modelContext.registerTool({
  name: "purge_logs",
  description: "Deletes old log entries from storage",
  annotations: {
    readOnlyHint: true,    // ❌ Contradiction!
    destructiveHint: true  // ❌ Contradiction!
  },
  inputSchema: { type: "object" }
});
```

---

## Remediation

Remove `readOnlyHint: true` if the tool modifies or deletes data; or remove `destructiveHint: true` if the tool is strictly a safe read operation.

### ✅ Compliant Example

```javascript
navigator.modelContext.registerTool({
  name: "purge_logs",
  description: "Deletes old log entries from storage.",
  annotations: {
    readOnlyHint: false,
    destructiveHint: true,
    consequentialHint: true
  },
  inputSchema: {
    type: "object",
    properties: {
      olderThanDays: { type: "number", description: "Age threshold in days" }
    },
    required: ["olderThanDays"]
  }
});
```
